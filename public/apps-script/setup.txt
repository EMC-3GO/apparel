# ANFFEL — Google Apps Script版の設置

この版は、アプリ画面・保存処理・報告書作成をGoogle Apps Scriptで実行します。
Google Cloudの無料トライアル、クレジットカード、OAuthクライアントID、Vercelの有料プランは不要です。
Googleアカウントの無料容量とApps Scriptの実行回数・実行時間の上限内で利用します。

## 初回だけ行うこと

1. 今まで使っていたANFFEL（https://apparel-18bv.vercel.app/legacy）を、記録を登録していたブラウザで開きます。左メニュー最下部の「データを引き継ぐ」でJSONを保存します。初期見本だけでよければ、この操作を省いてGoogle版を空から開始できます。JSONには記録内容が入るため、ご自身で保管してください。
2. https://sheets.new/ から、ご自身のGoogleアカウントで新しいスプレッドシートを作り、「ANFFEL 収支データ」と名前を付けます。
3. シートの「拡張機能 → Apps Script」を開きます。プロジェクト名を「ANFFEL」にします。
4. もともとあるCode.gs（コード.gs）の中身をすべて消し、配布用Code.gsの全文を貼り付けて保存します。画面とロゴも含まれているため、このファイル1つで動きます。HTMLファイルを別途作る必要はありません。
5. エディタ上部の関数選択から「setupAnffel」を選んで「実行」し、ご自身で作ったこのプロジェクトに必要なGoogleの権限を承認します。設定後、シートに「商品」「収支記録」「変更履歴」が用意されます。Google Cloudの課金登録は行いません。
6. 右上「デプロイ → 新しいデプロイ」を押し、種類を「ウェブアプリ」にします。「次のユーザーとして実行」は「自分」、「アクセスできるユーザー」は「自分のみ」を選択してデプロイします。「全員」にはしません。コード側でも設定したGoogleアカウント本人だけに制限しています。
7. 表示されたウェブアプリのURL（https://script.google.com/macros/s/…/exec）を開きます。今後はこのURLがANFFELの入口です。
8. 最初の画面で引き継ぎJSONを選び、件数を確認して「このデータを移行」を押します。既存データを使わない場合は「空のシートで始める」を押します。移行元のブラウザデータは自動削除しません。
9. いつも通りeditから1件登録し、保存先の「収支記録」に反映されることを確認します。ダッシュボードで累計／月別を選び「収支報告書を作成」を押すと、Googleドライブに報告書のスプレッドシートを作成し、PDFを取得します。

## 使い方

- 収入・支出・返品、商品登録の入力項目は従来のままです。
- 共通支出の自動分類、記録時単価の保存、受注生産の未確定表示を維持します。
- Google版ではブラウザの保存領域を収支の保存先にしません。端末を変えても、同じGoogleアカウント・同じウェブアプリURLで開きます。
- 保存完了まで入力画面は閉じません。通信等で保存に失敗した場合は入力を残します。同じ内容の再試行は操作IDで重複を防ぎます。
- 「商品」「収支記録」は現時点のデータです。「変更履歴」は途中で中断した保存の回復と再試行のために使用します。見出し・ID・更新ID・変更履歴は変更しないでください。
- 他のタブやスプレッドシート側で同じ記録を変更していた場合は、古い内容での上書きを止めます。入力を控えてダイアログを閉じ、右上の「Googleに保存」を押して最新データを読み直してください。
- 報告書は画面の検索条件ではなく、累計／月別で選んだ期間の全記録から作成します。同じ期間・同じデータでは直前の報告書を再利用します。データ更新後は新しい報告書を作ります。
- PDF取得だけ失敗しても報告書のシートは残ります。「スプレッドシートで開く」または「PDFを再取得」を使用してください。

## 更新するとき

Code.gsを新しい配布版へ置き換えます。setupAnffelを再実行しても、既存の正常なデータは消しません。
「デプロイ → デプロイを管理 → 編集 → 新バージョン」で更新すると、元のウェブアプリURLを継続して使えます。
新しく別プロジェクトを作ったり、公開対象を全員に変更したりする必要はありません。

## 開発・検証

- `npm run build:apps-script`：Viteでビルドし、サーバー集計処理・画面・ロゴを1つの配布用Code.gsにまとめます。
- `npm test`：集計、保存、再試行、競合、移行、権限制御等のテストを実行します。Apps Scriptサービスはテスト用の代替実装で検証します。
- `node tests/browser.mjs`：従来のローカル版操作を確認します（開発サーバーが必要）。
- `node tests/browser-apps-script.mjs`：配布用HTMLと実際のサーバー関数を、Googleサービスの代替実装を使って確認します。
- Google上での実際の権限承認、保存、PDF変換は、本人のアカウントで初回設置後に確認する必要があります。
