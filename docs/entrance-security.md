# Google側のパスワード入口と全体ロック

入口URL: https://apparel-18bv.vercel.app/
更新手順: https://apparel-18bv.vercel.app/apps-script/update.html

## 初回の切り替え（本人が操作）

1. 使用中のANFFELデータのスプレッドシートをGoogleドライブから開き、「拡張機能 → Apps Script」を選ぶ。
2. 更新ガイドからCode.gsをコピーし、同じプロジェクトのCode.gsを置き換えて保存する。
3. 左の歯車「プロジェクトの設定」から「スクリプトプロパティ」を開き、次の2つを追加する。既存のプロパティは消さない。

| プロパティ | 値 |
| --- | --- |
| ANFFEL_ACCESS_PASSWORD | 通常のパスワード。16文字以上。 |
| ANFFEL_RECOVERY_CODE | 通常のパスワードと異なる解除コード。16文字以上。 |

ランダムな24文字以上をパスワードマネージャーで作成することを推奨する。値はチャット・共有資料・コードに書かない。
Vercelに設定済みの値は自動で移さない。Google側のスクリプトプロパティへ本人が設定する。
同じ値を2つに設定した場合や未設定の場合は、管理画面を開けない。

4. 「デプロイ → デプロイを管理 → 現在のウェブアプリの鉛筆 → 新バージョン → デプロイ」で更新する。
5. 実行ユーザーは自分、アクセスできるユーザーは自分のみを維持する。新しいデプロイでURLを作り直さない。
6. 入口URLからGoogleへ進み、通常のパスワードで管理画面を開く。別ブラウザーも使い、3回間違えた後は全体がロックされ、解除コードで解除後に通常のパスワードの再入力が必要なことを確認する。

setupAnffelの再実行やデータの再移行は不要。商品・収支・受注・報告書を初期化しない。
この切り替えではGoogle側の更新と設定が必要。Vercelだけの更新ではGoogle上に全体ロックを導入できない。
以前のVercel環境変数 ANFFEL_ACCESS_PASSWORD は新しい入口では使用しない。削除は任意。

## 動作

- Googleの本人確認 → ANFFELパスワード画面 → 「ANFFELを開く」→ 管理画面。
- パスワードを連続3回間違えると、入口全体をロックする。成功した認証で失敗回数を0に戻す。
- 回数とロックはScript Propertiesに保存し、Script Lockで直列化する。別ブラウザー・端末・再デプロイ・キャッシュ消去では解除されない。時間による自動解除は行わない。
- 全体ロック時に既存の全セッションも失効させる。開いたままの管理画面でデータ操作しようとしても拒否する。
- 正しい通常パスワードだけではロックを解除しない。解除コードの成功後も未認証のまま通常ログインを要求する。
- 解除コードを連続5回間違えると解除の試行を30分止める。これは解除コードへの試行制限で、全体ロックの自動解除ではない。
- 解除コードを忘れた場合は本人がプロジェクトのスクリプトプロパティの ANFFEL_RECOVERY_CODE を新しい値に変更し、そのコードで解除する。ロック状態の内部プロパティを削除して直す手順にはしない。
- プロパティの値の変更はそのままサーバーに反映する。変更後、既存セッションは無効になる。コードを変更した場合だけ、新バージョンへのデプロイが必要。

## 保護する範囲と実装

- Google側の収支・商品・報告書・受注の全APIを、Googleアカウント本人確認とサーバーの認証セッション確認で保護する。
- 公開RPCは anffelRpc の許可リストを経由する。旧業務関数は末尾に _ を付け、google.script.runから直接呼べない。各業務処理のScript Lock取得後にもセッションと全体ロックを確認する。
- セッションは1時間のHMAC署名、ランダムなnonce、ロック時の世代、サーバーキャッシュの有効状態を確認する。ログアウトでキャッシュの該当セッションを削除する。
- Google HTMLのタブ内のsessionStorageに認証トークンを保管し、パスワード・解除コード自体は保存しない。トークンはHttpOnly Cookieではないため、アプリに外部スクリプトを追加しない。サーバーキャッシュは途中で失効しても再認証になるだけで、ロック状態は消えない。
- 認証情報はサーバーのスクリプトプロパティだけで確認し、公開コード・ログ・レスポンスには含めない。
- 設定不備・ロック状態の破損・セッション失効時は、データ操作を許可しない。
- スプレッドシートそのものの共有権限は引き続きGoogleが管理する。シートの所有者は直接編集でき、パスワード入口がGoogleの共有権限を置き換えるわけではない。
- 旧ローカル試作版 /legacy と公開ドキュメント・配布コードは以前通り公開される。Googleの実データや認証情報は含まない。

検証はGoogleサービスの代替環境とブラウザーで行う。本人のGoogle環境の設定・新バージョン公開・実保存は設置後に本人が確認する。
