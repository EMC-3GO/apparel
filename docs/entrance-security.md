# ANFFEL パスワード入口

公開URL: https://apparel-18bv.vercel.app/

## パスワード設定（本人が操作）

1. https://vercel.com/sango-takashimas-projects/apparel-18bv/settings/environment-variables を開く。
2. Add Environment Variable で Key を `ANFFEL_ACCESS_PASSWORD` にする。
3. Value に他のサービスで使っていない、ランダムな16文字以上のパスワードを入力する。パスワードマネージャーで24文字以上を生成することを推奨。チャットやGitHubには書かない。
4. Environment は **Production のみ** を選び保存する。Preview/Development は選ばない。
5. Deployments から最新の本番デプロイのメニュー → Redeploy で再デプロイする。環境変数は再デプロイ後に反映される。
6. 公開URLで、間違ったパスワードではボタンが出ず、正しいパスワードで「ANFFELを開く」が出ることを確認する。

パスワード未設定・16文字未満の場合は入口を閉じる。変更する場合も環境変数の編集と再デプロイが必要。変更すると旧パスワード由来のセッションは無効になる。

## 保護範囲

この入口は、認証されたブラウザーだけにApps Scriptへの移動を許可する。Google側アプリやスプレッドシート自体へのアクセス権はGoogleで管理する。Apps Scriptのデプロイは「自分として実行」「アクセスできるユーザー: 自分のみ」を維持する。所属組織のポリシーで選択肢が違う場合も、他人が使えない設定を確認する。入口はApps Script URLの直接アクセスを遮断しない。

旧プロトタイプは `/legacy`に残す。ブラウザー内の以前のデータの書き出し用で、入口の認証対象ではない。過去の公開資料・Apps Script配布コードも公開状態を維持する。保存されたGoogleの実データや入口のパスワードは含まない。

## 実装

- Vercel Node関数のみでパスワードを照合。固定長HMACの定時間比較を使用し、値をログやレスポンスへ出さない。
- 署名済みの1時間セッション。Secure / HttpOnly / SameSite=Strict / __Host- Cookie、no-store。パスワードから用途を分けた署名鍵を導出し、変更時に既存Cookieを無効化。
- 認証・ロック操作にOrigin検証。外部フレーム埋め込み禁止、外部スクリプトなしのCSP。
- 同一関数インスタンス内でIPごとに15分間5回の試行制限。これは補助的な制限で、Vercelの分散・再起動をまたぐ保証はない。短いパスワードには依存しない。大規模な総当たり対策が必要ならVercel Firewallまたは永続ストアによる共有制限を追加する。
- 「ロックする」は現在のブラウザーのCookieを削除。他端末からの一括失効はパスワード変更と再デプロイで行う。

環境変数設定後の本番で、正解・不正解・再読み込み・ロック・Google本人以外のアクセス拒否を確認する。Google側のアクセス設定はこのリポジトリから変更しない。
